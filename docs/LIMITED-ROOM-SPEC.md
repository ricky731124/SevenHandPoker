## 1. 名詞

| 名詞 | 意義 |
|---|---|
| **限定房** | 新房型（第三種，與一般房、特殊房並列）。玩法依星期決定，玩家不能自選。 |
| **玩法 / mode** | 限定房當天的規則。共四種：百鬼夜行、空城計、撲朔迷離、火力全開。 |
| **正牌** | 52 張裡沒被變掉的一般牌（限定房的牌組變化日只剩 7~A，共 32 張）。 |
| **開局鬼牌 / 開局空白** | 每人開局固定拿的 1 鬼 + 1 空白（SPEC §2.2）。id 為 `JOKER_p1` 等，`isStarterSpecial()` 可辨識。 |
| **牌組鬼牌 / 牌組空白** | 限定房由 2~6 變出來的鬼牌、空白牌。規則上跟開局那張**完全一樣**（鬼牌數照算、空白一樣不算數），只是 id 不同。 |

## 2. 總則（不能違反）

1. **舊的一行都不動**：一般房、特殊房、主線、教學的規則、比牌、boss 邏輯完全不變。限定房的新規則、新人機邏輯**只在限定房生效**。
2. **主線永遠不會有限定房**。大廳人機表演賽第一版**不打**限定房。
3. 限定房的入口：建立房間（對戰電腦 / 對戰好友都可選）、快速配對。
4. 玩法由「伺服器時間換算台灣時間的星期」決定（§9），朋友開房也要照當天玩法。
5. 舊資料相容：沒有 mode 欄位的房間、回放、引擎狀態一律當作非限定房。

## 4. 鬼牌比牌規則（百鬼夜行、撲朔迷離）

> 只套這兩種玩法。一般房、特殊房、火力全開照 SPEC §3 原規則（例如一般房單張鬼 = ♠A 會贏 ♣A）。

### 4.0 每格最多 2 張鬼牌（2026-10-28 定案）

- 百鬼夜行、撲朔迷離：**一格最多放 2 張鬼牌**，開局那張鬼也算。原因：鬼太多時每手都長成同花順 / 鐵支（實測同花順佔全部牌堆 47%），玩法單一。
- 鬼牌維持 20 張（2~6 全變鬼）。一人平均約 11 鬼，7 格最多用 14 張 → 某一方拿超過 14 張、鬼用不完的機率約 4.5%，當成一種平衡。送單張（不放鬼）會少掉 2 張鬼的位置，鬼多的人不能一直送。
- 選第 3 張鬼**選不起來**，跳提示「每格最多 2 張鬼牌」；連線時房主端收到對手出牌也再檢查一次（防舊版 / 作弊），超過就不收。
- 引擎本身不擋（`applyPick` 不檢查）：舊回放（沒有上限時錄的）照原棋譜重播不會壞。上限只在輸入端擋：玩家選牌、人機出牌、房主驗對手出牌。
- 下面 §4.1~§4.3 的估值與比牌規則不變；§4.3 裡 3 張鬼以上的例子現在百鬼打不出來，但保留當估值測試。

### 4.1 鬼牌怎麼變

- 一格裡**每張鬼牌各自**變成「讓這格牌型最大」的一張牌，**可以重複**（可以跟場上已有的牌、也可以跟同格另一張鬼牌一樣）。
- 沒有「五條」：牌型仍只有 SPEC §3 那 9 種。
- 參考：2 鬼 = 對子 A、3 鬼 = 三條 A、4 鬼 = 鐵支 A、5 鬼 = ♠ 同花大順（♠10 J Q K A）。
- 空白牌照舊忽略，也**不算進鬼牌數**。

### 4.2 決勝五步（前一步分出就停）

1. 比**牌型**。
2. 比**點數**（含踢腳牌；SPEC §3.1 原本「張數多的踢腳贏」照舊）。到這步都一樣 = 「**一樣大**」。
3. **這格鬼牌少的贏**。
4. 鬼牌一樣多 → 雙方**正牌**的點數由大到小逐張比，大的贏（點數照它在牌型裡的值，例如 A2345 的 A 算 1）。
5. 還一樣 → 雙方**正牌**的花色依牌型順序逐張比（♠ > ♥ > ♦ > ♣）。
6. 全一樣 → **平手**，該格金幣雙方各得（SPEC §2.3 原規則；雙方同時達成勝利條件的判定也照原規則）。

**攤牌說明字**：由第 3~6 步分出結果時，攤牌畫面多跳一行：

| 決定在 | 文字 |
|---|---|
| 第 3 步 | 牌一樣大・鬼牌少的贏 |
| 第 4 步 | 牌一樣大・正牌點數大的贏 |
| 第 5 步 | 牌一樣大・正牌花色大的贏 |
| 平手 | 完全一樣・平手 |

**一格多張鬼牌的攤牌顯示**：每張鬼牌都標出它變成什麼（沿用現有「鬼牌→♠A」樣式，支援多張）。

### 4.3 邊界例子（= 驗收用單元測試，全部要過）

正牌只有 7~A。

| # | 前者 | 後者 | 判決 | 決定在 |

| 1 | 5 鬼 | 5 鬼 | 平手 | 全同 |
| 2 | 5 鬼 | 4 鬼 + ♠A | 後者 | 3 |

## 5. 空白牌（空城計、撲朔迷離）

- 規則跟 SPEC §2.2 一樣：比牌時忽略，但佔張數。
- 全空白的格 = 無牌型，輸給任何牌；全空白對全空白 = 平手。沒有「用多用少」的問題。
- **空白也不算踢腳**：「張數多的踢腳贏」只算真牌（例：一對 A + 3 空白 輸 一對 A + 7）。
- **空白每格不限張數**（2026-10-29 使用者定，先不限，玩了再看）。

## 6. 火力全開（帶 5 用 3）

### 6.1 規則

- 牌組照一般 52 張，比牌照一般房規則。
- 帶最多 **5 張**特殊卡進場，整場最多用 **3 次**。
- **每張卡只能用一次**。
- **每回合最多用 1 張**；「回合」= 自己選牌的那一輪（整場 7 輪）。
- 帶不到 3 張（新手卡不夠）→ 帶幾張就能用幾次。
- 快配配到真人：照特殊房的**共同卡池**規則（`usableInMatch`）；朋友房各帶各的。
- 牌桌上顯示「**剩 N 次**」；用過的卡標成已用。

### 6.2 選卡畫面與預設

- 沿用特殊房的選卡畫面（`PreMatchSpecial`），格數改成 5。
- **限定房帶卡清單獨立存在帳號**（雲端），跟個人化的「特殊房預設 3 張」完全無關、互不影響；同一張卡兩邊都能放。
- 預帶規則：
  - 帳號裡有「上次限定房帶的卡」→ 預帶那幾張（重新快配、換對手、隔天、換手機都一樣）。
  - 第一次 → 預帶個人化裝備的 3 張 + 2 個空格讓玩家自己補。
  - 空格不補也能直接開打（就是少帶）。
- 選卡畫面按確認時存回帳號。訪客沒有帳號 → 存本機。
- 個人化面板**不加**限定房的欄位。
- 特殊房的預設邏輯**不改**（仍是個人化裝備的 3 張）。

### 6.3 引擎

- `specialUsed: boolean` 只給舊房型用；限定房改記「用了幾次、用過哪幾張、這回合用過沒」。舊房型行為不變。

## 7. 情報戰：推牌位置隨機

- 一般房：對手即時看到你推上來的牌在手牌的**位置**（SPEC §2 第 9 條）。
- **限定房（四種都一樣）：對手只看得到張數，推牌位置改成隨機顯示**。原因：依點數排序時空白在最左、鬼牌在最右，約 11 張一大塊，從哪裡推一看就知道，詐唬會失效。
- 實作：**由出牌那一端**產生假位置再送出（收到的一方拿不到真位置）。位置在同一次選牌中保持穩定：多選一張就多一個隨機位置，取消一張就少一個，不要每次全部重抽造成閃動。
- 自己的手牌、兩種排序方式照舊。
- 觀戰者本來就看全開視角，不受影響。
- 規則卡寫一句「對手只看得到你出幾張」。

## 8. 入口與畫面

### 8.1 建立房間

「房型」那列從 2 個改 3 個：**一般房 / 特殊房 / 限定房**（少一個「間」字，字級跟「對戰電腦」「50 秒」一樣大），水平排，限定房下面一行小字寫今天的玩法（例如「今日：百鬼夜行」）。小字**浮在按鈕下方、不佔高度**（跟按鈕留 4px）：對手↔房型、房型↔限時的間距維持原本一樣，彈窗不變高（2026-10-28 使用者回饋）。對手選「對戰電腦」或「對戰好友」都能選限定房。標題列右上角也有「?」（跟快速配對同一顆），點開看**輪值表**（2026-10-28 使用者回饋）。

### 8.2 快速配對

「一般房配對」「特殊房配對」下面加第三顆「**限定房配對**」，按鈕字後面接「・玩法名」小字（例如「限定房配對・百鬼夜行」，「・」跟玩法名同樣大小），按鈕下面不再多一行。三顆按鈕的圖示：一般房 ♠ 黑桃、特殊房 卡片、限定房 沙漏（2026-10-28 使用者定，原本三顆都是地球）。彈窗標題列右上角「?」（跟返回鍵同款同大小）點開看**輪值表**。

**輪值表**（2026-10-28 使用者定稿，原「一週表」）：標題「限定房輪值表」，同一種玩法的星期併成一列，玩法名對齊成一欄，今天那列標亮（例：星期三 → 「星期三、日 火力全開」那列）：

| 星期 | 玩法 |
|---|---|
| 星期一、四 | 百鬼夜行 |
| 星期二、五 | 空城計 |
| 星期三、日 | 火力全開 |
| 星期六 | 撲朔迷離 |

- 每列右邊一顆「**玩法介紹**」（橢圓框、圓體字，比一般小按鈕稍大），點了疊開那個玩法的規則卡（§8.3，不自動收），讓玩家玩之前先知道規則；規則卡「知道了」回到輪值表。
- 今天那列：**金框包住**（跟排行榜第一名同款金框），不換底色——避免跟「玩法介紹」按鈕的木色撞在一起。
- **沒有「知道了」**，改成標題列左上角返回鍵（2026-10-29 使用者回饋）。
- 星期欄不換行（「星期一、四」一行），彈窗寬一點；列少了 → 字放大、彈窗不用那麼高，手機上不要撐滿（下緣會卡到手機底部那條線）。
- 測試期固定玩法時表下多一行「測試期間每天都是百鬼夜行」；標亮的還是照真正的星期（2026-10-28 提前做，不等步驟 5）。
- 列的內容由 `LIMITED_SCHEDULE` 自動併出來（改排程表，輪值表跟著變）。

### 8.3 規則卡

VS 畫面之後跳一張規則卡：玩法名稱 + 2~3 行規則 + 「知道了」。火力全開則把規則寫在選卡畫面上方。文案（百鬼夜行是使用者 2026-10-28 定稿，其他三種照同樣句型，使用者可再改字）：

| 玩法 | 規則卡文字 |
|---|---|
| 百鬼夜行 | 點數 2~6（共 20 張）全部變成鬼牌。<br>每格最多放 2 張鬼牌。<br>對手只看得到你出幾張，無法看到你實際出牌的位置。<br>（範例欄：牌型和點數都一樣時：三步驟 + 範例，見下） |
| 空城計 | 點數 2~6（共 20 張）全部變成空白牌。<br>空白牌比牌時不算，但會佔張數——真真假假，讓對手猜。<br>對手只看得到你出幾張，無法看到你實際出牌的位置。<br>（範例欄：空白牌容易誤會的地方，見下） |
| 撲朔迷離 | 點數 2~6（共 20 張）裡 10 張變鬼牌、10 張變空白牌。<br>每格最多放 2 張鬼牌。<br>對手只看得到你出幾張，無法看到你實際出牌的位置。<br>（範例欄：同百鬼） |
| 火力全開 | 帶 5 張特殊卡進場，整場可以用 3 張。<br>每回合最多用 1 張，每張只能用一次。<br>對手只看得到你出幾張，無法看到你實際出牌的位置。 |

**比牌三步驟 + 範例（2026-10-28 定案，百鬼 / 撲朔迷離共用）**：原本「牌一樣大時，鬼牌用得少的贏；鬼牌一樣多…」一整句太繞，改成三步驟，每步一個範例，用**小張牌面圖**（左疊 vs 右疊、贏的打勾 + 一行說明），**規則卡上直接顯示**（不藏在按鈕後面）：

| 步驟 | 左 | 右 | 說明 |
|---|---|---|---|
| ① 鬼牌少的贏 | ♣A + 鬼 ✔ | 鬼 + 鬼 | 都是一對 A，左邊鬼少（順便示範兩張鬼 = 一對 A） |
| ② 鬼一樣多，比正牌點數 | ♠J ♠Q ♠K + 鬼鬼 ✔ | ♥10 ♥J ♥Q + 鬼鬼 | 都是 10~A 同花順，K 比 Q 大 |
| ③ 正牌也一樣，比花色（♠ > ♥ > ♦ > ♣） | ♦A + 鬼 ✔ | ♣A + 鬼 | ♦ 比 ♣ 大 |

**空城計範例（2026-10-29 定案）**：同樣兩欄、小牌面圖，標題「空白牌容易誤會的地方：」，三個都是**右邊贏**（打勾在右）：

| 範例 | 左 | 右 | 說明 |
|---|---|---|---|
| ① 空白不算牌 | ♠A + 4 空白 | ♣K ♦K ✔ | 5 張也可能只是單張 A |
| ② 空白也不算踢腳 | ♣A ♦A + 3 空白 | ♥A ♠A ♣7 ✔ | 一樣一對 A，7 當踢腳 |
| ③ 全空白輸給任何牌 | 5 空白 | ♣7 ✔ | 全空白對全空白才平手 |

範例資料在 `limited.ts`（每個玩法自己的範例 + 誰贏），單元測試用真的比牌規則確認。

- 版面（as-built）：有範例的玩法規則卡分兩欄——**左欄三步驟範例、右欄規則 + 「知道了」**（2026-10-28 使用者習慣「知道了」在右邊，兩欄對調；「知道了」在右欄水平置中；2026-10-29 「每格最多放 2 張鬼牌」拆成獨立一條 → 規則 3 條），三步驟範例（說明小字接在步驟標題後面），手機橫向不用捲；窄螢幕（≤ 560px）疊成一欄。標題字 26px（「限定房・百鬼夜行」原本會斷成兩行）。範例資料在 `limited.ts` 的 `TIE_STEPS`，單元測試確認三個範例照真的比牌規則、分在對的那一步。

連線對戰時規則卡 15 秒自動收起（避免一方一直開著，另一方乾等）；對戰電腦 / 快配人機不自動收。

### 8.4 牌桌標籤

牌桌常駐玩法**方鈕**（圓角方框，大小 = 右四鈕；字只寫玩法、兩字一行：「百鬼／夜行」「撲朔／迷離」「火力／全開」，空城計一行），點了再看一次規則卡。不寫「限定房」三個字。
**每種玩法一個顏色**（2026-10-29）：要避開牌桌紅布（酒紅）、LiveBoard / 彈窗的淺木色羊皮紙、金色。百鬼夜行 = 紫；空城計 = **灰藍**（空、冷清；先用看看）；撲朔迷離、火力全開做到時再定（提案：撲朔迷離青綠、火力全開炭黑底 + 橘色字框——橘色只當字和框，不整塊鋪，才不會跟紅布糊在一起）。
位置（2026-10-28 定案）：**右側控制群內欄、「?」正上方**，用右四鈕同一套變數等比定位：`right = --sbtn-r-in`、`top = --sbtn-top-q − --sbtn-gap-y` → 「?」到方鈕的距離 = 「花色/大小」到「?」的距離。左欄留給火力全開的特殊牌鈕。
- 直播觀戰：右欄沒有按鈕，方鈕照放同一位置，點了也能看規則卡。
- 回放：**不放方鈕**（點進回放前就知道是哪種玩法；右欄還有 1x/2x 倍速鈕）。
- LiveBoard 小標、回放清單只寫玩法名（「百鬼夜行」；清單是「快速配對 - 百鬼夜行」），不寫「限定房」，避免擠到編號 / 手機頭像。

- 星期 → 玩法寫成**一張設定表**（之後要限時段只改表）。另有「測試期固定玩法」開關：有設定時，不管星期幾都用那一種。步驟 1~4 期間依序固定為正在測的玩法。

## 11. 人機邏輯

### 11.1 原則

- **`bossAI.ts` 一行都不改**。新增一層「限定房邏輯」，只在限定房被呼叫；它可以**唯讀呼叫**原本的函式（候選牌組、收手時機、各卡觸發條件、放牌），但不改它們。
- 入口只加分派：`ai.ts` / `gameStore` 在限定房時改走限定層，其他情況完全照舊。
- boss 原本的個性參數**讀來調力道**：主策略（強攻 / 囤牌 / 平衡）、執行力、詐唬、看破。
- 對戰電腦（普通電腦，沒有 boss 個性）在限定房用同一層，套「平衡、中等詐唬、中等執行力」的預設個性。
- 快配人機：大腦照現在（隨機主線 boss 個性 + 抽主策略 + 執行力），只是改走限定層。

### 11.2 公平性：限定房看破關閉

原本 boss 的「看破」是模擬人類讀推牌位置（`readOrderTier`）。限定房對人類隱藏了位置（§7），所以**限定房 boss 的看破一律當 0**，只能讀張數；讓我看看（火力全開）看到的手牌照常可用，那是合法資訊。做法是傳入看破 = 0 的參數，不改原函式。

### 11.3 主策略在限定房的意思

主策略照原本機率抽，但意思變成「資源（鬼牌、真大牌、特殊卡）怎麼花」。**都要溫和**：

| 主策略 | 百鬼夜行 | 空城計 |
|---|---|---|
| 強攻 | 有牌就出，前期不送；**中期（第 3~5 手）可以棄一格**：這手湊不出鐵支 / 同花順（三條以下都算差牌），而且留著下一手有機會出鐵支 / 同花順 → 出「單張 + 1 鬼」（沒鬼才出純單張）。**整局最多棄 1 次**；後期出最好的 | 有牌就出、看未來比重低；詐唬多用「真大裝大」50%、「真大裝小」30%、「小牌裝大」20% |
| 囤牌 | **第 1 手預設送**（「單張 + 1 鬼」，沒鬼才出純單張），除非牌很好；第 2 手起看牌決定（節奏快，不能送太多）；後期不亂送 | 看未來比重高、前期願意送格（全空白 / 小單張）；前期多用「小牌裝大」約 60% 省真牌，後面兌現 |
| 平衡 | **有好牌就出、沒好牌就過渡**（「單張 + 1 鬼」，沒鬼才出純單張），「好牌」看比分：**落後**三條以上、**平手**鐵支以上、**領先**只有同花順或 K / A 鐵支。**整局最多過渡 2 次**；**後期不送** | 看未來比重中等；三種出法各約 1/3 |

前期 = 第 1~2 手、中期 = 第 3~5 手、後期 = 第 6~7 手。三種打法要保持差別，不能都變成囤牌。

- **過渡 / 棄一格一律用「單張 + 1 鬼」**（= 一對，還有基本戰力）；純單張只在手上沒鬼時出。（2026-10-28 定案：純單張多存 1 張鬼，但等於白送一格，效益差。）
- 已經過渡幾次看桌上自己的牌堆算（只有 1 張正牌、最多 1 張鬼的牌堆），重整 / 接手也算得出來。
- 放牌也分打法（§11.9）：強攻爭格子、平衡講 CP 值、囤牌能避戰就避。

### 11.4 百鬼夜行

#### 11.4a 第三版（2026-10-28 晚，每格最多 2 鬼，現行）

規則改成每格最多 2 鬼（§4.0）後，牌型重新變多元，下面 11.4b「只在大牌和送 1 張之間選」不再成立，改成「這手的價值 + 留下來的牌之後的價值」一起算：

- **候選**：所有 ≤ 2 鬼的組法——同花順（窗裡同花色正牌 ≥ 3）、鐵支（對子 + 2 鬼 / 三條 + 1 鬼）、葫蘆（三條 + 對子、兩對 + 1 鬼、三條 + 單張 + 1 鬼…）、同花、順子、三條（對子 + 1 鬼、單張 + 2 鬼）、兩對、對子（「1 真 + 1 鬼」= 過渡用）、單張。
- **這手的價值**（初值，做完用模擬看各牌型實際拿下格子的比例再調）：同花順、鐵支最高；葫蘆、同花常撞到鐵支，價值降一些；三條堪用；強對子（A/K + 1 鬼）拿來過渡；順子最差。
- **留下來的價值**：剩下的正牌 + 鬼（含之後預估補到的）還能湊出的牌（只用結構估算，不窮舉），乘上主策略的「看未來」比重。
- **鬼牌浪費**：剩下手數 × 2 裝不下手上 + 預估會補到的鬼 → 多出來的就是浪費，要扣分（逼鬼多的人每格都放滿）。
- 主策略：見 §11.3 表。實作上：強攻看未來比重低，平常不過渡、中期最多棄 1 格；平衡比重中等，照比分判斷好牌、沒好牌就過渡（最多 2 次）；囤牌第 1 手預設送（牌很好才出）、之後比重較高；**後期（第 6~7 手）三種都不送單張**（除非真的只能出單張）。
- **最後一手**：從整副手牌挑最大的組合（≤ 5 張、≤ 2 鬼），剩下的牌也塞進去當踢腳（張數多的贏）——留牌沒用。
- **差一格就贏（任一方）**：不管打法，出這手最大的。
- **執行力失手**：只看這手的價值、不看未來，出這手價值最高的。
- 只剩鬼牌：每格最多 2 張。
- **放牌**：限定房放牌（§11.9），讀百鬼的張數 → 牌型分布表。
- **執行力（2026-10-28 定案，只有百鬼）**：新放牌後百鬼人機比一般房難（模擬 vs 直覺玩家：百鬼快配平均約 62%、一般房約 53%），改用跟第一關鳥鳥一樣的執行力：**快配人機 0.35 / 0.5 / 0.65 隨機抽、對戰電腦固定 0.5**（原本 0.6 / 0.75 / 0.9、對戰電腦 0.75）。一般房 / 特殊房 / 主線不動。其他三種限定玩法做到時，看模擬勝率再決定。

#### 11.4b 第二版（2026-10-28 白天，每格不限鬼，已被 11.4a 取代）

步驟 1 第一版太弱（使用者 9 勝 1 敗）：鬼牌預算太緊湊不出同花順、「小牌不進同花順」寫太死、葫蘆 / 順子分數太高。重寫成下面這套：

- **核心觀念**：一人整局約 11 鬼、7 手，同花順一手要 2~3 鬼 → 不可能每手都出大牌，一定要送掉幾格。每手只在「出大牌」和「送 1 張」之間選。
- **大牌只有兩種**：**同花順（主）**、**鐵支（輔）**。都用「最多正牌、最少鬼」湊：同花順看每個花色每個 5 格窗（7-J、8-Q、9-K、10-A），窗裡同花色正牌全用上。
  - 同花順之間：**先比用的鬼少，再比頭大**（♣9 10 J + 2 鬼 勝過 ♣10 J + 3 鬼）。小牌可以進同花順；只禁「1 張小牌 + 4 鬼」（例 #12，比 5 鬼還小）。
  - 同花順 vs 鐵支：同花順**最多比鐵支多 1 張鬼**就選同花順，多 2 張以上才選鐵支。
  - 一手最多花 3 張鬼；「1 張牌 + 4 鬼」太耗，只有鬼很多（手上 + 預估之後補到的 ≥ 4 + 2.5 ×（剩幾手 − 1））或剩 ≤ 2 手才用。
- **中間牌**（葫蘆、順子、同花、三條、對子）不主動出：耗正牌又耗鬼還常輸，不如送 1 張。只有剩 ≤ 3 手又湊不出大牌時，才出正牌天然的成牌或「對子 / 三條 + 1 鬼」。不出「K + 鬼」這種單張配鬼。
- **送 1 張**：先把「能跟別張正牌一起湊大牌」的核心牌分出來（從最省鬼的組法開始分，例 ♦7 8 9 分走後 ♦K 就落單），從**落單的正牌裡送最小的**；全是核心牌才挑拿掉後損失最小的那張。
- **要送幾格**：估「手上正牌 + 鬼 + 之後補到的牌」還湊得出幾手大牌，不夠出滿剩下每一手的差額就是要送的格數；什麼時候送看主策略（§11.3）。
- **差一格就贏（任一方）/ 最後一手**：不省了，出最大的；湊不出大牌就出最大的中間牌（鬼全部可補，例 ♦10 + 2 鬼 = 三條）。
- **執行力失手**：不算省鬼、不送格子，直接出上限內最大的大牌（浪費一點鬼，但不會出怪牌）。
- **不主動出 5 張全鬼**：只有手上真的只剩鬼牌時才出（分散用）。
- **關掉「鬼牌留到關鍵時刻才用」**（鬼牌時機技能）。
- **放牌**：原本的 boss 放牌（看破 = 0），這次沒改。
- 驗收：使用者 2026-10-28 的五張截圖寫成單元測試（`limited.test.ts`「五張截圖」），強攻 / 平衡都要出對的同花順，囤牌前期可以送 1 張但不准出中間牌。

### 11.5 空城計

#### 11.5c 第二版（2026-10-30 定案，現行；取代 11.5a 的出牌 / 墊空白 / 放牌表 / 失手）

使用者實測快配 4 戰 4 勝。統計第一版快配電腦每手出什麼（400 場）：沒對子的單張（含墊空白）約 26%、全空白只有 5%、5 張真牌的大牌約 11%、三條只有 7%、強對子墊空白約 15%、「A / K + 鬼」湊對子再墊空白約 7%。原因：
- 失手 =「出最大」→ 葫蘆、順子這種 5 張真牌（一半手數是失手）。
- 價值表是電腦打電腦量的，**沒算花了幾張真牌**（CP 值）。
- 「看未來」把留下的單張也算價值，出單張和留單張差不多 → 常出 Q。
- 墊空白只看牌型、不分強弱。
- 放牌分布表也是電腦自己打自己量的：電腦愛把對子墊成 3 張 → 它以為「你出 3 張多半是對子 + 空白」，就拿自己的「對子 + 空白」去撞（忘了自己在詐唬）。真人出 3 張多半是三條。
- 模擬對手（不墊、每手出最大）跟真人差太多 → 模擬 53%，實測 4 戰 4 勝。

**做法：先把電腦調強（找出想法上的 bug），再用執行力調弱。** 模擬對手改成照使用者打法寫的「玩家模型」，跑執行力 1 / 0.75 / 0.6 / 0.5 / 0.35，**電腦勝率目標約 50~55%**（= 玩家 45~50%；只是模擬，實際以使用者實測為準）。

**空城計自己一套觀念**（使用者 10/30）：大部分對決（約 75%）落在全空白 / 高牌 / 弱對 / 強對 / 兩對 / 三條。**三條 CP 值最高**；兩對是不得已（但比一般房的兩對好，因為對手多半只是一對）；強對子依舊很強。鐵支、5 張的大牌除非不得已都算浪費——出 5 張真牌撞到一張空白，幾乎要兩手才補得回來。

出牌：
1. **手牌拆成「資產」**：三條、對子（**強對 J~A、弱對 7~10**）、鐵支；剩下的是單張。
   - **鬼**：優先把對子補成三條（補最弱的對子，提升最多）；沒對子就留著（最後兩手再用），**不拿鬼配單張湊對子**。
   - **鐵支**：不一定拆。使用者的習慣：50% 留鐵支、30% 拆成三條（多一張單張）、20% 拆成兩個對子。同一組鐵支整局只決定一次（用 seed，不會每手重抽）。**鐵支不墊空白**。
   - 資產比剩下的手數還多（真牌多到用不完）→ 把最弱的兩個併起來（兩個對子 → 兩對、三條 + 對子 → 葫蘆）。
2. **大牌**（鐵支以外的 5 張牌：順子、同花、葫蘆、同花順）只在三種情況出：**最後兩手**、**差一格就分勝負**（誰差都算）、**真牌多到用不完**（上一條的合併）。其他時候一律拆開出。
3. **沒資產 → 送格**：一律全空白（張數 1~3 隨機，偶爾 4~5），**不出單張**（手上沒空白才送最小單張）。偶爾（約 1 成）「最小的落單單張 + 3~4 張空白」裝大——只花 1 張沒用的真牌，對手拿全空白來撞反而送我一格（使用者：可保留，不用做太死）。
4. **有資產時這手出哪個 / 要不要先送**：估「手上資產 + 之後補牌大概還能湊出的資產」夠不夠出滿剩下的手數，不夠的差額就是要送幾格；什麼時候送、先出強的還弱的看主策略（初值：強攻有資產就出、先出強的；平衡看比分；囤牌前期先送、先出弱的；模擬再調）。
5. **墊空白**（詐唬，初值，模擬再調）：

   | 這手 | 墊法 |
   |---|---|
   | 三條 | 不墊 55%、墊 1（裝兩對）35%、墊 2 10% |
   | 兩對 | 不墊 80%、墊 1 20% |
   | 強對 J~A | 不墊 85%、墊 1 15%（強對墊空白只會招三條來撞） |
   | 弱對 7~10 | 不墊 50%、墊 1（裝三條）50% |
   | 鐵支 / 5 張大牌 | 不墊 |
   | 送格 | 見第 3 點 |

   強攻多「真大裝大」、囤牌多「小牌裝大」；boss「詐唬」個性高的多墊一點。空白預算照舊（一次最多平均配額 × 2）。
6. **最後一手**：真牌全塞（不變）。**差一格就分勝負**：真牌出最強的（大牌也可以），空白照墊（不變）。
7. **執行力失手**（使用者 10/30 定）：**照實出最划算的一手**——手上最強的資產，不墊、不看以後、不合併；沒資產就出 1 張空白。只是笨一點，不會自殺。執行力數字先不動，模擬完再一起調。

#### 11.5d 看棋盤（2026-10-30 使用者同意加，第二版之上）

第二版只看自己手牌決定出什麼；對手放我的牌時，是看「我出幾張」+「他各格等著的牌」決定。所以同一手牌在不同棋盤下該出的不一樣。這層讓電腦**出牌前先想對手會怎麼放**：

- **候選**：每個資產 × 墊 0~2 張（不超過空白預算），加上送格（全空白 1~3 張、偶爾單張 + 3 張空白裝大，整局最多送 3 格）。
- **模擬對手怎麼放**：對手在「我還空著的格子」裡挑一格放我的牌。他等著的牌我看不到，只知道張數 → 照分布表（讀人 + 算牌）抽一疊可能的牌，用**同一套放牌邏輯**站在對手那邊挑格子（他只看得到我出幾張）。抽很多次取平均：
  - 放到他有牌的格子 → 當場比，我贏 / 輸那格的價值（拿了就贏的格子價值很大 = 擋殺 / 搶殺）。

#### 11.5b 原始構想（2026-10-27，已被 11.5a 取代）

張數是對手決定「把你的牌放哪格」的唯一線索，空白牌讓這個線索不可靠。電腦**不會只丟 1 張空白當犧牲**（輸了也換不到東西）。混用三種出法：

1. **真大裝大**：強牌補空白到 5 張——讓「5 張」有時是真的大，對手不敢一律當假的。
2. **真大裝小**：強牌不補空白（一對 A 只出 2 張）——對手以為小，可能放去撞他自己的強格。
3. **小牌裝大**：單張或小對子補空白到 4~5 張——對手以為大，會放到對他沒影響的格子，電腦用很少真牌換掉對手一個好位置。

- 三種出法的比例由 boss 的「詐唬」個性 + 主策略決定，但**三種都會出**，讓張數跟強弱看不出關係。
- **不出整格全空白**；只有手上只剩空白被迫出牌時才出，出幾張照詐唬邏輯決定。
- **對手只差一格就贏 → 不詐唬，拿真牌守**。
- **放牌**：限定房放牌（§11.9），換成空城計自己的分布表：張數只當**上限**（2 張最多對子、3 張最多三條…），表等空城計出牌邏輯做完再用模擬產生；另加「同一局翻開過的牌」讀這個對手愛不愛墊空白（公開資訊）。

|---|---|
| 強攻 | 爆破、踏雪尋梅、永恆鑽石、正中紅心、塊桃鴨、死神之眼 |
| 囤牌 | 偷窺、偷天換日、讓我看看、強迫更新 |
| 平衡 | 各類混帶 |

**用卡**：
- 時機看**卡片本身**，不是「囤牌 = 晚用」。每張卡沿用原本的觸發判斷（唯讀呼叫）。
- 外加：一回合最多 1 張、用滿 3 次就停；前幾輪門檻稍高、後幾輪還有剩就放寬，不要帶著沒用完的次數結束。
- 局勢判斷例：發現對手在囤牌 → 強迫更新；讓我看看 → 下回合看到對手有大牌再強迫更新。這只是例子，卡種變多後再分析搭配。

### 11.9 限定房放牌（共用，2026-10-28 定案）

原本 boss 放牌用「張數 → 牌力」猜對手（4 張 ≈ 兩對、5 張 ≈ 同花），每格 2 鬼的百鬼完全不對：模擬裡 1 張 = 高牌、2 張 = 對子、3 張 = 三條 99%、**4 張 = 鐵支 96%**、**5 張 = 同花順 64%**（葫蘆 10%、順子 9%、對子 / 三條補踢腳 12%）。所以電腦常拿三條去接對手的鐵支。限定房（百鬼、空城計、撲朔迷離）改用限定層自己的放牌，`bossAI.ts` 不動；**火力全開是一般牌組，照舊用原本放牌**。

分四塊，三種玩法只差第 1 塊：

1. **分布表**（每種玩法一張）：對手出 N 張時，各種「牌型 + 點數 + 用幾張鬼」的機率。用模擬（人機互打）產生後寫進程式；出牌邏輯改了要重產。空城計 / 撲朔迷離做到時各補一張（空城計另加張數當上限 + 讀人，§11.5）。
2. **算勝率**：每一格，算「我這格的牌」贏 / 平 / 輸對方這疊的機率（照分布表逐一比：牌型 → 點數 → 鬼少的贏）。我這格還空著的話，對方這疊會留在那格等，之後由對方決定我哪疊去接 → 用它的強弱估之後輸掉的機會（對方挑，所以對我不利一點）。
3. **位置價值**：每格的價值 = 1 枚金幣 + 連著自己金幣的加成；拿了就直接贏（4 幣或 3 連）的格子價值很大，對手拿了就贏的格子同理（= 擋殺）。我這格的牌用掉了，之後就不能拿去接別的牌 → 強牌拿去壓小牌要扣「本來留著的價值」（CP 值）。
4. **打法權重**：
   - 強攻：爭格子——「留著的價值」扣得少（敢用大牌）、連線加成高、五五波也打。
   - 平衡：講 CP 值——「留著的價值」照算，挑剛好打得贏的格子，打不贏就拿最弱的牌認賠。
   - 囤牌：能避戰就避——丟到我這格還空著的格子有加分，只打很有把握的，輸的代價算重一點。
- **執行力失手**：不看打法和位置價值，只挑勝率最高的格子（小失誤，不會亂撞）。

### 11.8 驗收

- 單元測試：§4.3 全部例子 + 多鬼估值對拍 + 各模式組牌不違規（不塞小牌、不主動 5 鬼、不出全空白、不只丟 1 張空白）。
- 難度模擬（沿用 `difficulty.sim.test.ts` 方式）：每種玩法跑「限定層 vs 原本邏輯」「限定層 vs 隨機」，勝率報給使用者，確認人機強度跟現在快配差不多。
- 限制：電腦打電腦看不出詐唬騙不騙得到真人，那部分靠使用者實測。

## 12. 連線與資料

- **房型**：`RoomType` 加 `'limited'`；房間加 `limitedMode` 欄位（開房時寫入）。
- **引擎**：`GameState` 加可選的 mode 欄位（沒有 = 非限定房）。發牌、比牌、特殊卡次數、推牌位置都看這個欄位。host 權威不變，guest 拿到的狀態就帶著 mode。
- **牌組牌 id**：牌組變出來的鬼 / 空白用新 id（例如 `JOKER_d3`），`isStarterSpecial()` 仍只認開局那兩張。
- **回放**：記錄 mode；`createGame` 依 mode 建牌組，舊回放沒有 mode = 一般。
- **觀戰 / LiveBoard**：顯示玩法標籤。
- **舊版本擋門**：手機上還在跑舊版的人用房號加入限定房，會看不懂規則。舊程式本身沒有擋門，所以靠 **RTDB 規則**擋：限定房的 guest 加入時必須帶新版才會寫的欄位，舊版寫不進去就加入失敗。快配本來就按房型分開，舊版不會配進來。→ **需要使用者發布新規則**（實作時先確認現有 rules 結構再定寫法）。
- 配對節點本來就是萬用 key（`matchmaking/$type`），不用改規則。
- 實作：新版加入任何房間都寫 `guestVer: 1`；規則 `rooms/$roomId/.validate` 加一段「roomType 是 limited 且有 guestId → guestVer 必須是 ≥1 的數字」（見 `database.rules.json`）。一般房 / 特殊房不受影響。**規則發布前**限定房照樣能玩，只是還擋不到舊版。
- **版本 2（2026-10-28，每格最多 2 鬼）**：`ROOM_CLIENT_VER = 2`。舊版不會擋第 3 張鬼，所以這次**房主也要擋**：開房時寫 `hostVer`、加入時寫 `guestVer`；規則改成「限定房 → `hostVer ≥ 2`，有 guest 時 `guestVer ≥ 2`」。舊版開限定房會被規則拒絕、舊版加入也會被拒絕。→ **使用者要再發布一次規則**。
