# 手機橫向體驗 Spec（v2，2026-11-04）

> 狀態：**收斂中，還沒動手**。標 ❓ 的是還沒定案的。
> 備份點：git 標記 `backup/before-landscape`（= 7e69043）。

---

## 0. 一句話

**手機上不管是 iOS／安卓、網頁／安裝版、真橫向／假橫向，都用同一套畫面；開一個開場頁，負責安卓轉真橫向和引導玩家，之後也當節慶主題的展示頁。電腦版和 iPad 的畫面排版不動。**

---

## 1. 要解決的痛點

| # | 痛點 | 現在的樣子 |
|---|---|---|
| P1 | 假橫向跟真橫向長得不一樣 | 彈窗沒轉、牌局超小、大廳選單間距和 LiveBoard 字都不同 |
| P2 | 手機有四種排版要維護、要測 | 全螢幕、網頁有網址列、假橫向各自有修補 |
| P3 | 上方「請開啟自動旋轉」橫幅很醜 | 直拿就一直顯示 |
| P4 | 安卓網頁版不是真橫向 | 有網址列，方向要靠自旋 |
| P5 | 玩家不知道怎麼玩最好 | 只有網頁版大廳的「加到主畫面」小框 |
| P6 | 從 Threads 點進來沒有導出去 | Threads 沒偵測到 |
| P7 | 三星跑版 | 限定房按鈕壓到上方玩家名字 |
| P8 | 怕改壞 | — |

---

## 2. 定案的方針

1. **手機只有一套畫面。** 環境只決定「畫布縮多少、要不要轉 90°」。
2. **全程都是橫的。** 沒有直式入口頁。
3. **一定要導出內建瀏覽器。** FB、Threads、LINE、IG 都不在裡面玩。
4. **不強迫，但一開始就讓玩家知道最佳玩法，也告訴他不做會怎樣。**
5. **電腦版、iPad 不動。**
6. **每一步都要能退回。**

## 3. 要改的東西

### 改動 A：手機「單一畫布」（解決 P1、P2）

**做法**
- **邏輯畫布 = 這支手機橫放、全螢幕時的大小**（螢幕長邊 × 短邊）。每支手機照自己的大小排版（定案：A1-甲）。
- 最外層只有一個「外框」，負責兩件事：
  1. **縮放**：整塊畫布等比縮到實際看得到的範圍。背景、按鈕、字、牌一起縮。全螢幕時縮放 = 1；Safari 有網址列時大約 0.75~0.8
  2. **旋轉**：手機是直的，就整塊轉 90°（假橫向）
- 彈窗、通知、成就提示全部放進畫布裡，跟著一起縮、一起轉。
- 瀏海和動態島由外框統一讓位。
- 大地圖拖曳、捲軸，在假橫向時把手指移動的方向對調。
- 刪掉各自的修補：網頁版彈窗固定 0.8、牌局另外算的縮放、假橫向專用的尺寸覆寫。

**實作（第 1 階段，as-built）**
- `src/platform/canvas.ts`：算畫布大小、縮放、旋轉，寫到 `#root` 的寬高和 transform；剛好等於視窗、不縮不轉時不放 transform（全螢幕、電腦版跟改版前一模一樣）。
  - 手機 = 觸控＋螢幕短邊 < 600。看得到的範圍是直的就轉 90°。
  - 畫布高 = 螢幕短邊（跟全螢幕同高，版面高度分段一樣）；縮放 = min(1, 看得到的高 ÷ 畫布高)；**畫布寬 = 看得到的寬 ÷ 縮放**（寬度補滿，網頁版兩側不留空邊）。全螢幕時剛好 = 螢幕長邊、縮放 1。
  - 寬度限制在 16:9（iPhone SE 比例）~ 2.8 倍高之間，超出才留一點邊（例：iPhone 網頁版直拿，左右各約 18px）。
  - 網頁版寬度可能超過 1024 → 電腦版排版條件一律寫 `@container app (min-width: 1024px) and (min-height: 481px)`（手機高度到不了 481）。
  - 大廳主圖在比 2.25:1 還寬時（只有網頁版會）：主圖最寬 2.25:1 置中，兩側用同一張圖模糊補滿、接縫漸層淡掉；選單按鈕改以高度為上限（`Menu.css`）。
  - 電腦／iPad：畫布 = 視窗。iPad 直拿照舊轉 90°（改版前就是這樣）。
  - 打字中（鍵盤開著）不重算畫布；鍵盤吃掉的高度照舊交給彈窗的 `--vvh`（換成畫布座標）。
- `#root` 是 CSS 尺寸容器（`container-type: size; container-name: app`）。
  - 全站 `vw/vh/dvh` 改成 `cqw/cqh`。
  - 尺寸條件 `@media (max-height…)` 改成 `@container app (…)`。
  - 容器自帶 layout containment，所以裡面 `position: fixed` 的東西也以畫布為準。
- 瀏海：`canvas.ts` 用探針量 `env(safe-area-inset-*)`，扣掉縮小後留的黑邊、除以縮放，再依旋轉對應到畫布的四邊，寫成 `--sa-l/--sa-r/--sa-t/--sa-b`。元件一律用這四個變數，不再直接用 `env()`。
- 彈窗、通知、回放控制、觀戰層全部 portal 到 `#root`（`portalRoot()`），跟著轉、跟著縮。
- 量位置的程式（特效飛行、回放控制貼齊舞台、大地圖拖曳、鍵盤時把欄位捲到中間）一律換成畫布座標：`canvasRect()` / `toCanvas()`。
- 拿掉的舊修補：
  - `global.css` 直拿旋轉那一大段。
  - 牌局另外算的縮放（`useFitScale`）。
  - 網頁版彈窗固定縮 0.8（`--mw-scale`、`--safe-mult`）。
  - 網頁版 BATTLE／擲硬幣上移 5%。

**對你現在的 iPhone（主畫面開、有開自旋、真橫向）**
- 畫布大小 = 現在的大小，縮放 = 1，所以**遊戲畫面上的位置要完全一樣**，唯一多的是開場頁。
- 用基準照做像素比對來保證。如果比對出差異（例如統一瀏海讓位，讓大廳或牌局移了幾 px），會先拿改前改後截圖給你看，你同意才保留。

**緊急出口：假橫向可以整個關掉**
- 旋轉只寫在外框一個地方，所以有一個開關可以關掉。
- 關掉的話：手機直拿時不再轉 90°，改成顯示一整頁「請開啟自動旋轉並橫放手機」，轉成真橫向才進遊戲。
- 代價：**iOS 鎖直向的人一定要開自旋才能玩**（安卓不受影響，點擊開始就會鎖成真橫向）。
- 假橫向最後做不好，就切這個開關，不用整包倒回去。

### 改動 B：開場頁（解決 P3、P4、P5）

**一頁，不會有第二頁、第三頁。**

**長相（背景圖要盡量完整露出）**
- 跟大廳**同一張背景圖**（定案：B3），只輕微壓暗，不模糊，讓圖完整露出
- 標題沿用大廳現有的標題；下方一行會閃的「點擊畫面開始」
- 提示卡是**角落的小卡片**，木紋加遊戲字體，跟現有按鈕同一套風格，**不蓋住主圖**
- 點小卡片：跳出木紋引導彈窗（圖解），按 ✕ 回到開場頁。**還是同一頁**
- 點畫面上小卡片以外的任何地方，就開始：暗色退掉，淡入成大廳
- 東西還沒載完時先顯示「載入中」，載完才換成「點擊畫面開始」

**為未來的主題預留（這次不做商城）**
- 開場頁拆成三層：**背景圖 / 特效層 / 文字和小卡片**
- 背景圖和特效從同一個「主題」設定讀取。這次只有一個預設主題（= 現在的大廳背景、沒有特效）
- 之後要做聖誕節、過年主題，或用鑽石買背景加特效（下雪、煙火），只要新增一個主題，不用改開場頁
- 開場頁背景跟大廳背景讀同一個設定，所以換主題時兩邊一起換

**提示卡：看當下狀態，不記錄、不猜**

| 提示卡 | 誰會看到 | 什麼時候消失 | 卡上寫的「不做會怎樣」 | 點下去的圖解 |
|---|---|---|---|---|
| 開啟自動旋轉 | 只有 iOS，**當下畫面是假橫向**（手機回報是直的）時 | 系統真的轉成橫向的那一刻，**當場消失**；轉回直的又出現 | 「沒開自動旋轉：打字會很不方便XD」 | 右上往下滑 → 點鎖頭；附「已經開了？把手機稍微立起來晃一下」 |
| 加入主畫面 | iOS，在 Safari 開 | 從主畫面圖示打開就不會出現 | 「沒加主畫面：上下有網址列，畫面比較小」 | 沿用現在的加主畫面引導內容 |
| 安裝 App | 安卓，在瀏覽器開，而且還沒安裝 | 已安裝或從安裝版開就不會出現 | 同上 | 沿用現在的一鍵安裝和安裝完成提示 |

- 「開啟自動旋轉」卡**跟現在那條醜橫幅用同一個判斷**：手機回報是直的就出現，回報是橫的就消失。差別只是從醜橫幅變成開場頁上的一張卡。
  - 上一版寫的「轉過一次就永久打勾」**取消**，改成照你說的看當下狀態。
- 「加主畫面／安裝」的引導**不重做**：把現在大廳那個引導的內容和判斷搬到開場頁。大廳的小框拿掉（定案：B2）。
- 用房間邀請連結（`?room=`）進來時，維持現在的做法：加主畫面的提示比較低調，因為加了主畫面也回不到這個房間。
- 全部都做到的人，開場頁就只有 Logo 和「點擊開始」。

**點擊開始那一下做的事**
- **安卓**：進全螢幕並鎖成橫向，變成真橫向，不管有沒有開自旋
  - 瀏覽器不支援的話，退回假橫向
  - 切出 App 再回來時，全螢幕會被系統取消；下一次點畫面就默默重新進全螢幕
- **所有平台**：解鎖音效，背景同時預載大廳需要的東西

**誰會看到開場頁**
- 所有手機，每次冷開（從零打開或重整）都會看到
- 切出去再回來不會看到
- 用 `?room=` 邀請連結進來：一樣先看開場頁，點擊開始後直接進房間
- 電腦、iPad：看 B4
- 在內建瀏覽器裡的人：不會看到，他們看的是導出教學

**引導內容的版本差異**
- iOS 和安卓不同版本的按鈕位置不一樣，例如 Safari 的分享鈕可能在下面、上面或「⋯」裡；FB 的 ⋯ 位置也會變。
- 引導的文字和圖集中放在一個設定檔，遇到新版本再改那裡就好。這次先照目前主流版本做。

**移除**：上方「請將手機轉為橫向…」橫幅（OrientationTip）。

**B1（定案：甲）**：不多跳「建議設定」卡，提示卡只放在開場頁上。沒做到就一直出現，但不強迫。

**❓ B4：電腦和 iPad 要不要也有開場頁？**
- v2 原本寫「不會看到」，原因是電腦、iPad 不用轉向、不用鎖全螢幕，兩張提示卡也都用不到。
- 但開場頁之後要當主題展示（節慶、鑽石買的背景和特效），所以改建議：**所有平台都有開場頁**，電腦和 iPad 只是沒有提示卡。
- 好處：主題大家都看得到；電腦瀏覽器播聲音也要先點一下，開場頁剛好一起解鎖。
- 電腦已經安裝的人（電腦版 Chrome 也能安裝），一樣只看到乾淨的開場頁。
- 在內建瀏覽器裡的人，看到的是導出教學，不是開場頁，因為他們在裡面不能玩。

## 5. 怎麼保證不改壞（P8）

1. **另開 git 分支做。** 線上只從 main 部署，分支怎麼改都不影響線上。
2. **改之前拍基準照。** 幾種手機的全螢幕尺寸，每個畫面各拍一張（以你的 iPhone 尺寸為主）：大廳、開始遊戲彈窗、牌局、回放、個人化、排行榜、主線地圖、商城、限定房、教學。
3. **改完自動比對：**
   - 全螢幕真橫向、電腦版 → 跟基準照**像素相同**
   - 假橫向轉回來 → 跟真橫向**像素相同**
   - 網頁版 → 跟全螢幕縮小後相同
4. **自動檢查工具**：用各種尺寸跑過全部畫面，抓按鈕重疊和超出畫面。以後交付前都跑一次。
5. **真機只測模擬器測不到的**：鍵盤、瀏海、安卓全螢幕鎖橫、Safari 網址列。
6. **橫向的改動集中在自己的 commit。** 上線後不行，可以只撤銷這幾個。

**工具用法（`scripts/layout/`）**
- `node scripts/layout/snap.mjs shoot <名稱>`：拍完整一輪（12 台 × 40 個畫面 ≈ 460 張，同時拍 3 張，約 35 分鐘），存到 `_layout/<名稱>/`（裡面有 `report.md` 檢查報告）
  - `--quick`：**快速檢查**，平常改一步就跑這個（7 台 × 10 個畫面 = 70 張，約 5 分鐘）。哪些算快速檢查看 `devices.mjs`／`scenes.mjs` 裡標 `quick: true` 的。
  - `--dev ios-full,and-web`：只拍某些裝置（裝置清單在 `devices.mjs`）
  - `--only lobby,game-ai`：只拍某些畫面（畫面清單在 `scenes.mjs`）
  - `--jobs 3`：同時拍幾張。開到 4 張 Chrome 會吃不消當掉，預設 3；某張失敗會自動重拍一次，瀏覽器當掉會自己重開。
- `node scripts/layout/snap.mjs sheet <名稱>`：總覽圖，一個畫面一張、所有裝置排在一起（存到 `_layout/<名稱>/_sheets/`），另外產一頁 `index.html` 可以直接翻。
- `node scripts/layout/snap.mjs compare <a> <b>`：逐張比對像素，差異圖存到 `_layout/diff-a-b/`
- 加主畫面提示卡在拍照前會先按掉（第 2 階段會拿掉它，留著會蓋住底下、前後比對也會全是它）；另外有一張 `a2hs` 專門留著它。
- 聊天內容：截圖瀏覽器刻意連不到 Firebase（免得被選成聊天主持往正式聊天室發話），聊天畫面改用開發模式的 `window.__fakeChat([...])` 餵假訊息（`src/net/lobby.ts`，不寫 DB；訊息內容在 `scenes.mjs` 的 `fakeChat`）。
- 拍不到的（等真機測）：貼圖飛出、玩家名片、LINE／安卓 FB（直接轉走，沒有畫面）。
- 截圖用的瀏覽器連不到 Firebase 和 Google，登入狀態是假造的，所以不會影響線上（不會算進在線人數、不會發聊天、不會寫入資料）。
- 亂數、時鐘都固定，同一份程式拍兩次結果會一模一樣。做法（以後拍不穩時先查這幾條）：
  - 假時鐘暫停，只有 `settle(ms)` 會照固定步數往前推；等載入（Vite 編譯、圖片）時用真時間，不動時鐘。
  - CSS 動畫一開機就設成 0 秒；framer-motion 打開 `MotionGlobalConfig.skipAnimations`（它的淡入不歸假時鐘、也不歸 CSS 管）。
  - 亂數固定種子，每個畫面開始前再重設一次；Firebase 自己用原本的亂數（它連不上時重試的時間點不固定）。
  - 點擊直接對元素 `click()`，不靠座標（假橫向畫面是轉過的）。
- 自動檢查只看「看得到的」東西：被別的圖層整個蓋住的不算；文字換行時逐行量。刻意疊在一起的元素可以標 `data-layout-ok` 略過。
- `compare` 會把差異分成「明顯不同」和「細微（<1%，多半是大圖解碼的雜點）」。
- `_layout/` 不進 git。

## 8. 基準照檢查結果（2026-11-05，改版前）

基準照：`_layout/base/`（12 台 × 41 個畫面，總覽圖在 `_layout/base/_sheets/`，`index.html` 可直接翻）。

### 8.1 第 1 階段（單一畫布）會一併解決的
- 假橫向（主畫面開但直拿、Safari 直拿、安卓直拿）整個版面跟真橫向不一樣：
  - 彈窗沒跟著轉：牌型速查、回放的對決彈窗是直的疊在轉過的牌桌上。
  - 個人化、商城、設定、排行榜被排成直式（窄長一條）。
  - 主線地圖變成直的，章節頁籤被切掉 50～108px。
  - 牌局縮得超小。
  - 限定房規則彈窗變一欄，「知道了」被切到看不到。
- 網頁版（iOS Safari、安卓 Chrome、S25 網頁）：
  - 大廳的三顆主選單按鈕蓋到「Poker」Logo。
  - 火力全開選卡的第二排卡、特殊房選卡的第三格被切。

### 8.2 自己決定要修的（第 1 階段一起做）
- **矮螢幕的彈窗太高**（小台安卓 360 高、S25 全螢幕 384 高；單一畫布後這些手機的畫布高度還是一樣，所以要另外修）：
  - 歡迎彈窗：「訪客進入」被切一半（iOS 全螢幕、S25），小台安卓完全看不到。
  - 建立房間：「建立房間」鈕被切。
  - 火力全開規則：「知道了」被切。
  - 每日任務：最下面那行說明被切。
  - 設定：「牌背」那列被返回鈕壓住。
  - 做法：彈窗內容超過可用高度時整個等比縮小到放得下（現在網頁版固定縮 0.8，改成依高度自動算）。
  - 使用者補充：三星實機上，很多 iPhone 不用滾的彈窗都要滾（火力全開規則卡不滾只看到半個「知道了」）。
- 小台安卓的牌局：電腦的「5 張」泡泡貼到暫停鈕 → 泡泡往上移一點、字小一點點（只差一點點，不要大動）。
- **遊戲中「發動特殊牌」彈窗（火力全開帶 5 張）**：寬 460 放不下 5 張，變成上 4 下 1；三星還因此要滾。→ 拉寬到 5 張排一排（iPhone 也一起改）。
- **限定房右側的玩法方鈕壓到對手名字**（改動 E / P7）：小台安卓確定壓到（名字前 3 個字被蓋），其他手機只差 4～6px，安卓真機字型行高較高就會壓到。
  - 做法：右側原本 4 顆鈕不動，只有玩法方鈕在「離對手名字太近」時往下讓（量對手頭像＋名字的實際底部，方鈕最高只到名字下方 8px）。

**怎麼修的（第 1 階段，as-built）**
- 矮螢幕彈窗：`src/ui/hooks/useFitHeight.ts`。
  - 量彈窗內容全高（含面板裡 `.panel__scroll` 藏起來的部分）。
  - 超過「看得到的高度 × 0.92」（矮螢幕 0.95）就整塊等比縮到剛好放得下，最多縮到 0.72，再小就留捲軸。
  - 面板的 max-height 用 `--fit` 放大回去。
  - 用在所有 `Modal` 和設定頁。商城、排行榜、個人化、回放清單、玩法說明本來就是長清單要捲，不縮。
- 發動特殊牌（火力全開）：彈窗寬 460 → 560，五張排一排。
- 限定房方鈕：`Game.tsx` 量對手頭像＋名字的實際底部寫成 `--foe-bottom`。
  - 方鈕 `top = max(原位置, 名字底 + 8px)`，右側 4 顆鈕不動。
  - iPhone 全螢幕也會往下 1～2px（名字底 + 8 剛好比原位置低一點）。
- 「5 張」泡泡：只在畫布高 ≤ 370（小台安卓）時改貼在對手名字下方 2px，字 12px。
- 電腦版標題斷行：
  - 標題列沒有返回鍵也沒有右邊小鈕時，標題用滿整列（`.modal__titlebar--solo`）。
  - 歡迎／登入彈窗在電腦版加寬到 500。
  - 觀戰／回放的對決彈窗右上角另外疊了「×」，照舊左右留欄。
- 驗證（`_layout/p1full/`，510 張）：
  - 全螢幕（iOS、安卓）、電腦版：跟基準照像素相同，只有上面刻意修的畫面不同。
  - 假橫向轉回來 = 真橫向（`rotpair`），只差左邊「請轉橫向」橫幅（第 2 階段拿掉）和文字反鋸齒。
  - 新增的重疊只有網頁版「加主畫面」小卡的 ✕（第 2 階段拿掉），以及回放進度條貼著名字差不到 1px（全螢幕本來就這樣）。

### 8.3 使用者決定（2026-11-05）
1. **回放暫停時控制鈕疊在對決彈窗／手牌上：維持現狀（甲）。** 刻意的：把回放當影片，控制鈕一定在最上層；繼續播放幾秒後自己藏起來，暫停時才一直在。已經是半透明。
2. **電腦版：配對等待標題斷兩行、歡迎彈窗標題斷三行 → 要修。**（電腦版「不動」的例外：這是原本就有的錯）
3. **手機聊天室沒有標題列和返回鍵 → 使用者原本要補，但我看錯了：** 補上假訊息重拍後確認，手機平常有標題和返回鍵（跟電腦同一套）。只有「點輸入框打字、鍵盤開著」時刻意藏起來（`LobbyChat.css` 的 `lchat-modal--kb`），讓訊息區塞得進鍵盤上方。收起鍵盤就回來。→ 不改。原則記下：以後加好友功能也兩邊同一套。
4. **觀戰彈幕蓋到第 7 格和「火力全開」方鈕：維持。** 位置不夠、彈幕已經比較透；有更好的解法再討論。
5. **截圖要有聊天內容：要。** 加一個只在開發模式才有的假訊息入口，聊天相關畫面拍有內容的。
