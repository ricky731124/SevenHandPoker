# Boss AI 設計與調校記錄

關卡 boss 的打牌邏輯全在 `src/game/bossAI.ts`(共用工具在 `aiCore.ts`)。這份文件記錄
**目前的能力邊界、難度實測、已知限制、變更記錄**,給未來反覆調校用。每款遊戲的打法
是 GAME CONTENT;此檔隨 boss AI 一起演進。

## 模型概觀
- **主風格**(每局 `rollMain` 抽一次):強攻 attack / 囤牌 hoard / 平衡 balance。權重在
  `campaign.ts` 每隻 boss 的 `profile.pickMain`。
- **副技能**(0~100 發動率):詐唬 bluff / 拼牌 draw / 鬼牌時機 jokerTiming / 看破 insight。
- **執行力 execution**(x-1/x-2/x-3 = 0.6 / 0.75 / 0.9):`sharp()` 每個決策擲一次,失敗就
  退回「原始最強 / 過度投入」的笨版。**這是主要難度旋鈕**——0.6 約 40% 決策會失手。

## 出牌(`bossPick`)
- **cpValue 效益權重**:三條最高、中強對(≥7)高、兩對/順子略扣(耗多張)、單張高牌=認輸該格。
- **強攻 `attackPick`**:取最強前 4,挑「打完後留下的下一手最好」(前瞻)。
- **囤牌 `hoardPick`**:囤牌期優先 三條 → 中強對(7~10 / JQKA);**禁高牌、禁弱對(22/33)**。
  **收手轉攻邊界**:輸 ≥2 幣,或(先攻已出到第 4 手 / 後攻第 3 手)→ 兌現最強成牌。
- **平衡 `balancePick`**:收手期兌現最強;否則**保留 5 張大牌**,在其餘候選挑
  `cpValue +(剩牌還有 4 同花/4 順的活抽?+25)`,並對高牌領牌 -40 → 常領中強對、留牌拼更大
  (對應「有順子+AA 時先出 AA、留順子牌」)。
- **拼牌 / peek**:非收手期,peek 用 `peekHoldPick` 一般化留牌(補牌後能成的任何升級都算);
  無 peek 時 draw% 於低槓桿留 4 同花/4 順。
- **鬼牌**:**必須升階**才用(禁當跳張、禁高牌→一對)。用時 `bestJokerCombo` 按「鬼牌用途效益」
  挑:葫蘆/三條 > 同花 > 順子(SF/鐵支自然最高)+ 後手。`jokerTiming` 高 → 升幅 <4 階的低槓桿
  把鬼牌收起來留給高槓桿。
- **詐唬 `padBluff`**:只 3 種、全配空白牌、不燒真牌 —— ①空白+最弱單張 ②空白+中強對
  ③空白+三條。

## 放牌(`bossPlace`)— 佈局 / 犧牲(基礎能力 × 執行力)
- **牌力階 `tierScore` 1~11**:強5張(SF/葫蘆)11、鐵支10、同花9、順8、強三條7、弱三條6、
  兩對5、強對4、中對3、弱對2、高牌1。
- **incoming 推估階 `it`**:spy → 讀真實階;否則 `countTier`(純張數)與 `readOrderTier`(讀出牌序
  推真實階)**依看破值線性內插**——看破 0 = 純張數(原佈局);越高 = 越接近真讀。`readOrderTier`
  把那疊照 rank 升冪排開、忽略空白墊張(→ 看穿詐唬:一對+空白讀成一對而非三條),用結構
  (同階群 / 連續 / 同花 / 鬼牌補強)判牌型。**七手撲克選牌會即時照排序把牌推出來,是刻意做的
  資訊戰信號 → 讀它是正當的**(spy 仍獨立:全手牌確定情報 + 影響出牌)。
- **評分**:贏面用「剛好夠贏的最弱牌」吃(超殺越多扣越重、**5 張大牌超殺懲罰加倍** → 不拿葫蘆撞一對);
  均勢小賭;明顯輸用**最弱牌認賠**。**擋殺 / 自己三連**才准強撞弱。失手(低執行力)退回舊的「梭最強去撞」。

## 資訊牌(`bossChooseSpecial`,x-3 多卡時)
- **EV 排序選一張**:花色(能湊成同花時)≈ spy ≈ peek ≫≫ swap(價值極低)。spy 對高看破加成、
  peek 對高拼牌加成 → 高看破/高拼牌 boss 早期就選資訊牌。
- **spy**:放牌讀真實階(完美看破)+ 出牌側 `shouldCashOut` 用手牌快照提早收手。
- **peek**:`peekHoldPick` 一般化留牌規劃。
- **花色牌(踏雪/永恆/紅心/桃)**:只在已握 ≥4 該花色、轉第 5 張真的成同花才用;避開拆對子;
  ≥5(已同花)只在雙用牌可釋放時轉。

## 難度實測(vs 基礎 AI「只出最強」,隨機先手,N=120)
| 關 | x-1(.6) | x-2(.75) | x-3(.9) |
|----|----|----|----|
| s1 哪裡來的鎹鴉? | 51 | 68 | 63 |
| s2 明天開始168 | 53 | 58 | 60 |
| s3 魚與熊掌我全都要 | 51 | 49 | 54 |
| s4 萌即是正義 | 51 | 54 | 63 |
| s5 奴才別打擾朕睡覺 | 48 | 50 | 53 |
| s6 情緒勒索的吉祥物 | 53 | 60 | 58 |

**為何不是 80%+(預期內)**:①先攻有優勢(競速搶幣/連線 + 抽牌 tempo);②基礎 AI「只出最強」
不弱,加上「對手幫你放牌 + 盲放 + 硬幣翻面」的高變異結構,技術優勢天花板本就壓向 50%;
③執行力手感(0.6 有 40% 決策失手);④boss 的細膩打法(囤牌紀律/看破/留拼牌)是**懲罰會犯錯、
會詐唬的對手(=真人)**才有價值 → 對真人會比表上更難。**要更難就調 `campaign.ts` 的 execution。**

**看破 A/B(x-3)**:s2 看破70→60% vs 看破0→64%(Δ-4);s6 看破60→58% vs 看破0→62%(Δ-4)。
→ 對**不詐唬**的基礎 AI,看破反而略降(無牌可看穿、只是變過度謹慎);其價值在對會詐唬的真人。

## 已知限制 / 未來可做(AI 打牌能力進步方向)
1. **算牌(card-counting)**:用公開盤面(已 showdown 的牌 + 自己手牌)縮小對手可能手牌,未做。
2. **鬼牌后手深度**、**平衡的權重**、各技能對「真人」的實際效果都待真人實測後再調。
3. **看破的量化驗證**:目前對「只出最強」的基礎 AI 中性(無牌可讀)、對「只會領弱牌+墊空白」的
   笨 bluffer 也因對手太弱而測不出差(boss 本來就全贏)。看破的價值需**對會策略性詐唬的真人**才顯現;
   單元測試已證明機制正確(高看破看穿墊張去搶幣、低看破被唬到避戰),勝率增益待真人實測。
