# Boss AI 設計與調校記錄

關卡 boss 的打牌邏輯全在 `src/game/bossAI.ts`(共用工具在 `aiCore.ts`)。這份文件記錄
**目前的能力邊界、難度實測、已知限制、變更記錄**,給未來反覆調校用。每款遊戲的打法
是 GAME CONTENT;此檔隨 boss AI 一起演進。

## 模型概觀
- **主風格**(每局 `rollMain` 抽一次):強攻 attack / 囤牌 hoard / 平衡 balance。權重在
  `campaign.ts` 每隻 boss 的 `profile.pickMain`。
- **副技能**(0~100 發動率):詐唬 bluff / 拼牌 draw / 鬼牌時機 jokerTiming / 看破 insight。
- **執行力 execution**(x-1/x-2/x-3 = 0.6 / 0.75 / 0.9):`sharp()` 每個決策擲一次,失敗就
  退回「原始最強 / 過度投入」的笨版。**這是主要難度旋鈕**——0.6 約 40% 決策會失手。

## 出牌(`bossPick`)
- **cpValue 效益權重**:三條最高、中強對(≥7)高、兩對/順子略扣(耗多張)、單張高牌=認輸該格。
- **強攻 `attackPick`**:取最強前 4,挑「打完後留下的下一手最好」(前瞻)。
- **囤牌 `hoardPick`**:囤牌期優先 三條 → 中強對(7~10 / JQKA);**禁高牌、禁弱對(22/33)**。
  **收手轉攻邊界**:輸 ≥2 幣,或(先攻已出到第 4 手 / 後攻第 3 手)→ 兌現最強成牌。
- **平衡 `balancePick`**:收手期兌現最強;否則**保留 5 張大牌**,在其餘候選挑
  `cpValue +(剩牌還有 4 同花/4 順的活抽?+25)`,並對高牌領牌 -40 → 常領中強對、留牌拼更大
  (對應「有順子+AA 時先出 AA、留順子牌」)。
- **拼牌 / peek**:非收手期,peek 用 `peekHoldPick` 一般化留牌(補牌後能成的任何升級都算);
  無 peek 時 draw% 於低槓桿留 4 同花/4 順。
- **鬼牌**:**必須升階**才用(禁當跳張、禁高牌→一對)。用時 `bestJokerCombo` 按「鬼牌用途效益」
  挑:葫蘆/三條 > 同花 > 順子(SF/鐵支自然最高)+ 後手。`jokerTiming` 高 → 升幅 <4 階的低槓桿
  把鬼牌收起來留給高槓桿。
- **詐唬 `padBluff`**:只 3 種、全配空白牌、不燒真牌 —— ①空白+最弱單張 ②空白+中強對
  ③空白+三條。
- **送格(2026-11-02)**:不單出鬼;送格送「最沒用的」牌(`junkCards`:沒成對、低、不是同花 / 順子的料、有鬼時 Q 以上留著),
  手上普通牌 ≥ 5 張送 2 張(對手分不出是一對還是高牌),更少送 1 張。手上沒任何成牌:收手期出「鬼 + 最大那張」,其他時候送格。
- **看棋盤 + 反推(2026-11-02,一般牌組:一般房 / 特殊房 / 主線 / 火力全開)**:
  只在「這手要用鬼」或「前 3 手要出 5 張大牌」時介入(偷窺 / 拼牌留牌等其他決定不碰)。三種打法都看棋盤,個性靠看未來比重 + 打法加分保住
  (強攻最看現在,第 1 手出葫蘆仍最多)。只讓平衡看前段大牌時,強攻 / 囤牌對舊打法只剩 47~49%,所以三種都看。`boardRefine` 把打法選的那手跟其他出法
  (不用鬼 / 鬼只升一點 / 每種牌型最強的 2 個 / 送格)一起丟進 `limitedPlace.blankBoardScores`:
  對手等著的牌照 `NORMAL_TABLE`(張數 → 牌型分布,`GENN=1` 產)抽、死神之眼翻開的照真牌,模擬對手會把這疊放哪,
  得到這手的期望;再加 看未來(留著的牌之後 3 手湊得出多少)× 打法比重(強攻 0.45 / 平衡 0.75 / 囤牌 0.95)
  − 用鬼成本 0.3 + 鬼牌用途加分(三條 / 葫蘆 / 鐵支 +0.25、順子 −0.1)+ 打法自己的選擇 +0.2。
  例:兩對 + 鬼,對手只放了兩疊 2 張 → 出一對 K、留 5 5 + 鬼;對手放了一疊 5 張 → 用鬼升葫蘆。
  **反推(第二段)**:我出的牌夠強(贏隨便一疊 ≥ 55%)時,對手沒拿他等著的那幾疊來撞 → 那幾疊「打得過我」的可能 × 0.4
  (使用者:「他 5 不敢撞我 5,頂多小葫 / 同花」)。存在 WeakMap(每個 BossRuntime 一份),不用改呼叫端。
  參數 `BOARD_TUNE`(`on = false` 回舊打法,模擬比較用;`debug` 可印各選項分數)。

## 放牌(`bossPlace`)— 佈局 / 犧牲(基礎能力 × 執行力)
- **牌力階 `tierScore` 1~11**:強5張(SF/葫蘆)11、鐵支10、同花9、順8、強三條7、弱三條6、
  兩對5、強對4、中對3、弱對2、高牌1。
- **incoming 推估階 `it`**:spy → 讀真實階;否則 `countTier`(純張數)與 `readOrderTier`(讀出牌序
  推真實階)**依看破值線性內插**——看破 0 = 純張數(原佈局);越高 = 越接近真讀。`readOrderTier`
  把那疊照 rank 升冪排開、忽略空白墊張(→ 看穿詐唬:一對+空白讀成一對而非三條),用結構
  (同階群 / 連續 / 同花 / 鬼牌補強)判牌型。**七手撲克選牌會即時照排序把牌推出來,是刻意做的
  資訊戰信號 → 讀它是正當的**(spy 仍獨立:全手牌確定情報 + 影響出牌)。
- **評分**:贏面用「剛好夠贏的最弱牌」吃(超殺越多扣越重、**5 張大牌超殺懲罰加倍** → 不拿葫蘆撞一對);
  均勢小賭;明顯輸用**最弱牌認賠**。**擋殺 / 自己三連**才准強撞弱。失手(低執行力)退回舊的「梭最強去撞」。

## 資訊牌(`bossChooseSpecial`,x-3 多卡時)
- **EV 排序選一張**:花色(能湊成同花時)≈ spy ≈ peek ≫≫ swap(價值極低)。spy 對高看破加成、
  peek 對高拼牌加成 → 高看破/高拼牌 boss 早期就選資訊牌。
- **spy**:放牌讀真實階(完美看破)+ 出牌側 `shouldCashOut` 用手牌快照提早收手。
- **peek**:`peekHoldPick` 一般化留牌規劃。
- **花色牌(踏雪/永恆/紅心/桃/漫天梅花)**:先找「改 ≤上限張就成同花順」(`suitStraightFlushVictims`,鬼牌可補洞,
  手上有強牌也照用);再湊同花(`suitVictims`:握 3 換 2、握 4 換 1、漫天梅花握 2 換 3;落單散牌優先)。
- **招牌是花色卡的 boss 本尊(3/4/5/6/10 關,2026-11-12 使用者:要推廣,x-2 ≥9 成、x-3 ≥7 成)**:
  每手最先判斷自己的花色卡(排在讓我看看 / 死神之眼等前面),用寬鬆版 `suitVictims(loose)`:可拆 10 以下的對子
  (每對拿一張)、鬼牌算同花一張;J 以上對子、三條不拆。x-2 不合理就不用;x-3 前 3 手只等自己的卡
  (`OWN_SUIT_WAIT`),第 4 手起還沒用就改用其他卡。

## 已知限制 / 未來可做(AI 打牌能力進步方向)
1. **算牌(card-counting)**:用公開盤面(已 showdown 的牌 + 自己手牌)縮小對手可能手牌,未做。
2. **鬼牌后手深度**、**平衡的權重**、各技能對「真人」的實際效果都待真人實測後再調。
3. **看破的量化驗證**:目前對「只出最強」的基礎 AI 中性(無牌可讀)、對「只會領弱牌+墊空白」的
   笨 bluffer 也因對手太弱而測不出差(boss 本來就全贏)。看破的價值需**對會策略性詐唬的真人**才顯現;
   單元測試已證明機制正確(高看破看穿墊張去搶幣、低看破被唬到避戰),勝率增益待真人實測。

### 備忘(原待辦 4~6;2026-11-03 使用者決定不排)
4、5 改由**人機回報**(`.claude/skills/bot-report`,決策帳本 `docs/BOT-DECISIONS.md`、情境題庫 `src/game/botScenarios.json`)逐題處理;
6 是大工程、做了不一定比較好 → 只當備忘,回報一直修不好「後段爛尾」時再啟動。以下保留當時的想法。
(2026-11-02 原註:難度可能已經夠了,「打新手打到不會贏」不是想要的。)

4. **看棋盤後的打法機率化(三種風格要不一樣)**。現在三種打法都看棋盤,但差別只靠「看未來比重 + 打法自己的選擇 +0.2 + 雜訊」,
   大多時候仍選分數最高的那個 → 越調越像同一個最佳策略。要改成「依情境給機率」:
   - 對手待對決有 5 張時:強攻 有信心(自己 5 張夠強)→ 高機率 5 張對撞;平衡 看自己 5 張夠不夠強,約五五波 出 5 張 / 出一對避戰;
     囤牌 想囤 → 高機率出一對避戰。夾不夾詐唬照各 boss 的技能。
   - 作法方向:各選項分數 → 依打法的溫度 / 偏好做 softmax 抽,而不是取最大;DIAG 印「各打法在同情境的選擇分布」驗證三種有拉開。
5. **鬼牌用途機率化**。例「4 梅花 + 一對 A + 鬼」現在看棋盤幾乎都選鬼補同花、留 AA。使用者的打法是兩種約各半,再依情境偏:
   - 對手待對決 3 張 → 偏 AA + 鬼(三條);5 張 → 偏同花。
   - 要跟對方拼牌 / 需要葫蘆這種必勝牌時,可能 AA + 小對 + 鬼。AA 是強對,也可以單獨打出去、鬼留著等。
   - 原則:不該是「一定怎麼出」,要寫成機率。影響很大,做完要跑勝率表。
6. **整場怎麼分配(「後段沒牌」)**。現在每手只看「這手 + 留下的牌之後 3 手的估值」,第 6~7 手仍有 50~60% 是散牌或弱對。要根治得做整場規劃:
   - a. 規劃:把手牌 + 之後會補到的張數(DRAW_SCHEDULE)切成剩下 N 手的出牌順序(候選疊的組合搜尋 / 貪婪 + 回溯),這手出「最佳整場規劃的第一步」。
   - b. 保底:剩牌不能完全沒成牌 → 後段至少留 1~2 組能打的(一對以上),否則扣分。
   - c. 看盤面花力氣:強牌花在能決定勝負的格子(連線 / 搶幣領先),已經定了的格子送散牌。
   - d. 驗收:DIAG 第 6~7 手散牌率明顯下降、勝率不掉;新 vs 現在 ≥ 52%;主線表。
   - e. 難度顧慮:做了 boss 會更強 → 可能只給 x-3 / 高執行力,或同時下修執行力。
