# 人機回報

使用者打完看回放，挑出人機怪手回報給你。**使用者不一定對**。你要：
- 自己想清楚使用者說的合不合理；
- 查跟以前定的原則有沒有衝突，有衝突就提出來討論；
- 不要無腦照改。

最怕的是 A 蓋 B、C 又蓋 A。

2026-11-03 第一次回報（辛棄疾 1010、KKK 出 KK、玉皇送格…）就是這樣做的，看 `docs/BOSS-AI.md` 變更記錄和 commit `85023f3`。

## 0. 使用者的回報格式（給他看的範本）

```
人機回報
1. 鼓山金城武 vs 今天辛棄疾 11/03 01:12
   - 辛棄疾第1手｜該出 AA｜不行｜先手，強對比較有價值
   - 辛棄疾第2手｜三條K或K三條+鬼｜不行｜拆三條浪費
2. 我要驗牌 vs 鼓山金城武 11/03 01:50
   - 我要驗牌第3次放牌｜放第2格｜不划算｜…
```

每題五欄：**誰的第幾手｜該怎麼出｜嚴重度｜原因**，外加場次（誰打誰 + 大概時間）。
- **嚴重度**
  - 不行：很不合理，失手也不准。
  - 不划算：CP 值低。
  - 偏好：可以，但我不會這樣出。
- **可以不寫**：原因、它實際出了什麼（你從回放看得到）。
- **手牌、對決區不用寫**，你自己抓。
- **格式不完整也照收**，缺的自己從回放補，真的對不到才問。

## 1. 抓回放

```powershell
powershell -NoProfile -File scripts/fetch-replays.ps1 -Name 鼓山金城武
```

- **名字**：填回報裡的真人玩家，可以用逗號給多個名字。
- **輸出**：`_replays/latest.json`（已 gitignore），內容是那個人最近的回放加上全站精華。
- **公司憑證**：會擋 curl 和 node fetch，所以這支腳本用 `Invoke-WebRequest`。腳本存檔要用 UTF-8 BOM，不然 PS 5.1 讀中文會壞。

**列場次**，用時間和對手對到 id（取 id 末 6 碼）：

```powershell
$env:BR_LIST='1'; npx vitest run botReport
```

**找不到那場**時，跟使用者說，請他給截圖或描述。原因可能是：
- 每人只留最近 8 場，被新的蓋掉了；
- 線上中離的場次不存回放。

## 2. 每題做情境卡

```powershell
$env:BR_CASE='tApWhr:辛棄疾:1;tApWhr:辛棄疾:2;tApWhr:鼓山金城武:3:放'; npx vitest run botReport
```

- **格式**：每個 case 是 `場次id片段:誰:第幾手`，結尾加 `:放` = 第幾次放牌。
- **用完清掉**：`Remove-Item Env:BR_*`。`BR_N` 是抽樣數，預設 400；`BR_STYLE='id1,id2'` 用來推測舊回放的打法。

**情境卡會印出：**
- 場次、模式；
- 人機的大腦（`brain`）：打法、執行力、技能參數用哪關 boss、帶了哪些卡。2026-11-03 之後的回放才有，舊的要用 `BR_STYLE` 推，而且程式改過以後推不準；
- 比分、雙方出牌數、牌堆剩幾張；
- 用過的特殊卡，以及偷窺 / 讓我看看拿到的資訊；
- 雙方手牌；
- 7 格棋盤，標出誰等著對決、對手的牌人機看不看得到；
- 前面幾步；
- 實際出的牌；
- 照它的大腦重跑的分布；
- 三種打法在執行力 1 時的分布；
- 失手（執行力 0 = 直接出最強）的分布。

**判斷這手是怎麼來的：**
- 它的大腦常出這個 → 是設計出來的選擇，要改邏輯。
- 只有失手路線會出 → 是執行力造成的。執行力低可以換另一種做法，但不能做蠢事；如果失手路線本身很蠢，要修的是失手路線（`bossAI.ts` 的 `!sharpPick` 那段）。
- 現在的程式已經不會這樣出 → 跟使用者說已經修過了（附現在的分布），不用再改。
- 使用者說的那手在所有分布裡都是 0% → 先查 `aiCore.candidatePiles` 有沒有產生那手。2026-11-04 的「鬼補皇家同花順」就是候選牌根本沒有，不是邏輯選錯。

## 3. 想清楚，再回給使用者（還不要改程式）

**每題先自己判斷：**
1. **使用者說的合不合理？** 要看局面：
   - 對手對決區有幾疊、各幾張；
   - 先手還是後手；
   - 第幾手、比分；
   - 手上的特殊卡和已經知道的資訊（偷窺到要補什麼）。

   你覺得有更好的出法、或使用者漏看了局面，就直說，附理由。
2. **查 `docs/BOT-DECISIONS.md` 和 `src/game/botScenarios.json`：** 有沒有哪條原則或哪一題跟這個要求衝突？有衝突就把兩邊攤開問使用者，例如「D05 說留牌時照樣出有戰力的，這題你要它送格，哪個優先？什麼局面下？」
3. **怎麼寫：**
   - 「不行」才寫死；
   - 「不划算」寫成扣分；
   - 「偏好」寫成機率或加分。
   - 能用「看棋盤」（`boardRefine` 的分數）表達的，就不要另外加 if。

**回覆格式**，每題一段，短：

```
#1 辛棄疾第1手(囤牌 0.75)
局面:先手、對手對決區空、0:0。手牌 AA 1010 鬼 K Q 8 7 6 5 空
它出 1010:囤牌想清楚時 57% 會出(打法邏輯「留大牌」),不是失手
你說:出 AA(不行)
我覺得:同意;另外兩對 AA1010 我認為也可以(你沒提),要不要算可接受?
衝突:無 / D0x(…)
打算:同牌型只看最大 → 題目 avoid「10 10」,失手也不准
```

**等使用者回覆**確認或修正，才進第 4 步。使用者說「照你說的」也算確認。

## 4. 改程式 + 加題

1. **加題**：每個確認的題目寫一個 spec 檔，跑 `node scripts/add-scenario.mjs spec.json`，題目會加進 `src/game/botScenarios.json`。
   - 欄位說明寫在腳本開頭。
   - 牌的描述寫法看 `src/game/botReport.ts` 的 `pileMatches`：`A A`、`類:對子`、`含:鬼`、`張:>=5`、`送格`、`格:3`。
   - 「不行」題一定要寫 `avoid`。只有使用者明確說「該出 X」時才寫 `prefer`。
2. **更新帳本**：`docs/BOT-DECISIONS.md` 新增一條原則，或修改舊的那條，並寫進「修改紀錄」。
3. **改 `src/game/bossAI.ts`**（火力全開也走 `bossPick`；限定房其他玩法是 `limitedAI.ts`）。
   - 新行為用開關包起來，像 `PICK_TUNE.fix1103` 那樣，方便新舊比較。
4. **驗證**：
   - `npx vitest run botScenarios`：全部舊題都要過。改出牌時加 `SCEN_N=200` 再跑一次。
   - 把新題「改之前」的版本跑一次，確認它原本會失敗。做法：把開關關掉，或複製成 zz_ 檔，用完刪掉。
   - 全套 `npx vitest run`、`npx tsc -b`。
   - 勝率（照 `src/game/fix1103.sim.test.ts` 的做法）：新 vs 舊、打基本 AI 三種打法、第 1 手和第 7 手的散牌 / 弱對比例。勝率掉很多（> 5%）要先跟使用者講。
5. **回報**：每題改了什麼、模擬數字、哪些題的分布變了。**沒說 commit 就不要 commit。** 使用者說「測完直接上版」才 commit push（身分 ricky731124，不要加 tsconfig.tsbuildinfo）。

## 注意
- 題庫跑得慢，一題約 3 秒。題目超過 40 題時，考慮把 `SCEN_N` 預設降低，或拆檔。
- 回放的 `brain` 從 2026-11-03 起才有；技能參數和帶卡是之後的版本才加的，舊回放只有打法和執行力。
- 只記得大概時間的場次，用 `BR_LIST` 對時間（台灣時間）。同一場可能出現兩筆（雙方各存一份），挑一筆就好。
